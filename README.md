# Pico色じゃんけんゲーム

1Pがゲーム用Wi-Fiの親機・進行役、2Pが子機です。ゲーム通信にはPC・外部ルーターは不要です。

## 遊び方

赤＝グー、緑＝チョキ、青＝パー。両者の色が読み取れたら、色の安定を待たず3秒のカウントダウンを開始します。開始時のつまみ値を目標として保存し、カウント終了時に読み取り・受信済みの最新の手で勝敗を判定します。カウント中は手を何度でも変更できます。終了時に色が判別できない場合は勝敗を決めず準備へ戻ります。

敗者は3秒でつまみを調整し、勝者の事前目標値との差が10以内なら防御成功です。値は−100〜＋100、5サンプル平均を使用します。目標値は相手への表示状態に含めません。2Pの締切値はタイムアップ通知後に取得するため通信遅延が乗ります。

防御成功ならカウンターでじゃんけんの勝者のサーボを60°進め、防御側をそのラウンドの勝者にします。防御失敗なら防御側のサーボを60°進めます。攻撃・カウンターを受けた回数を合計し、0°→60°→120°→180°と進みます。3回受けるとGAME_OVER、電源を手動で切って終了します。破裂の検出・自動電源断はありません。終了まで最終角度を保持します。通信断では未確定ラウンドをやり直し、累積被弾回数を維持します。再起動で被弾回数をリセットします。

## 接続と設定

| 部品 | 接続 |
| --- | --- |
| スピーカー | GP0、デューティ32768（50%） |
| 縦型LED | GP2、8個。0〜3＝自分、4〜7＝相手 |
| 丸型LED | GP4、8個 |
| TCS34725 | I2C1、SCL＝GP11、SDA＝GP10、アドレス0x29 |
| 可変抵抗器 | GP26 |
| サーボ | GP15、50Hz |

サーボ角度は指令値です。実際の0〜180°全域は未計測で、以前の動作確認は75〜105°でした。最初の全域試験では針を外して可動域を確保してください。

## 開始手順

1. 1P、次に2Pへ給電します。
2. 5秒の起動待機後、1Pが専用Wi-Fiを起動し、2Pが接続します。サーボは0°へ移動します。
3. 色とつまみ値を設定します。両者の色が読めたら自動カウントが始まります。手はカウント終了直前まで変更できます。
4. 敗者は防御音から3秒以内につまみを調整します。
5. 攻撃またはカウンターを合計3回受けると終了します。電源を切り、両方を入れ直すと再戦できます。

縦型は手の色を上下に表示し、カウント中は赤が2→4→6→8個に増えます。丸型は成功時に虹色回転、失敗時に赤点滅、勝利時に白フラッシュと紫、最終勝利時に金色です。

## ファイルの区分

- ルートのゲーム用Pythonファイル：Picoで実行するコード。
- `scripts/`：PCで使う任意の保存・ログ監視ツールと、その設定・依存ライブラリ。
- `tests/`：PCで実行するテスト。

Picoへ保存するのは、`boot.py`、`main.py`、`game.py`、`config.py`、`wireless.py`、`hardware.py`、`effects.py`、`color_sensor.py`の8ファイルです。Thonnyで手動保存する場合は、scripts/の準備は必要ありません。

## 開発・実機への保存

PC用ツールはPython 3.10以上、Pico側はMicroPython 1.27.0のPico W向けバージョンで確認しています。

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r scripts/requirements.txt
cp config_example.py config.py
cp scripts/devices.example.json scripts/devices.json
```

1. Thonnyのシェルで各Picoの固有IDを取得します。

   ```python
   import machine
   print(machine.unique_id().hex())
   ```

2. `config.py`のPLAYERSのキーを取得した1P・2Pの固有IDへ置き換え、可変抵抗器の校正値を設定します。GAME_SSIDとGAME_PASSWORDは両機共通です。Wi-Fiパスワードは8文字以上の任意の値へ変更してください。
3. `scripts/devices.json`にも同じ固有IDと各PicoのUSBポートを設定します。macOSでは`/dev/cu.usbmodem...`、Windowsでは`COM...`などです。
4. Thonnyを閉じてから、次で保存します。

   ```sh
   python3 scripts/install_game.py
   ```

保存前にPicoの固有IDを照合し、旧ファイルをbackups/へ保存します。全8ファイルを一時ファイルへ送信してSHA256で照合した後、保存名を切り替えます。更新中は電源を切らないでください。保存後の再起動は行いません。

`config.py`・`scripts/devices.json`は端末固有の設定としてGit管理から除外しています。公開する際には設定例だけを更新してください。

## USBでリアルタイムログを見る

両PicoをUSBでPCへ接続し、次を実行します。

```sh
python3 scripts/watch_pico_logs.py
```

時刻とプレイヤー名を付け、状態変化をGAME、3秒ごとの接続情報をLINK、サーボ移動をSERVOで表示します。センサー値の毎回の読み取りログはありません。監視は読み取り専用で、Ctrl+CはPC側の監視だけを停止します。

既定のUSBポートはscripts/devices.jsonを参照します。ポートが変わった場合は更新してください。個別に指定する場合は`python3 scripts/watch_pico_logs.py ポート名`です。Thonnyなどが同じUSBポートを使用中の場合は閉じてください。ゲーム通信はPico同士のWi-Fiで行い、WebREPLは起動しません。

各Picoは給電・再起動の5秒後に自動起動します。起動時にはサーボが0°へ動きます。

## コード構成

ゲームの流れはgame.pyに集約しています。待機→準備→カウント→じゃんけん判定→防御→結果→次ラウンド／終了の順です。通信値を回収するDEFENSE_SAMPLEは、防御の締切後に2Pの値を受け取るための段階です。

防御成功時はカウンターで相手のサーボを60°進め、ラウンドの勝敗を反転します。成功した本人は虹色回転と6連続のド音、カウンターされた相手は赤点滅と負け音です。防御失敗なら防御側が被弾します。どちらの場合も、今回被弾した側が合計3回に達したらゲーム終了です。

| ファイル | 担当 |
| --- | --- |
| game.py | ゲーム全体のコア。じゃんけん・防御判定・状態遷移・メインループ |
| wireless.py | P2P通信とパケット検証 |
| hardware.py | センサー・LED・音・サーボの入出力 |
| effects.py | LEDパターン、音階とメロディ |
| color_sensor.py | TCS34725の通信・設定・RGB補正・色判定 |
| config.py | 配線・ルール・校正・接続設定 |
| boot.py / main.py | 国設定 / 5秒待機してゲーム開始 |

Picoへも上記の8ファイルをそのまま保存します。不要になったreferee.py・rules.py・tcs34725.pyは統合・削除しました。通信の状態名をDEFENSEへ変更したため、実機へ保存する際は両Picoを同じバージョンに更新してください。

判定と演出のテストは次で実行します。

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
```

## 防御成功音

実機の音をイメージした擬似音です。ド（C5・523Hz）を70ms鳴らし、35ms休む組を6回繰り返します。指定時間の合計は630msで「ドドドドドド」と鳴ります。実際は更新間隔により少し長くなります。実機の採譜や音源の再生ではありません。音量設定は32768（50%デューティ）です。
